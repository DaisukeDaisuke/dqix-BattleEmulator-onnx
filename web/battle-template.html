DQ9 共通バトル・カメラ探索

戦闘条件とseedを入力し、ダメージ・状態変化・乱数・カメラを共通グラフで計算します。row+4の候補を実測と照合し、残った全ての枝から続けます。

モデルを展開しています。

戦闘と探索の条件

WebGPUでは未対応演算の自動CPU代替を禁止しています。倍精度カメラ演算は明示したWASMモジュールで実行します。

row+4の候補領域

空の条件 {} は、実際の入力境界に必要な各ワードの全uint32値（0〜4294967295）を表します。候補を少しずつ列挙し、計算上限に達したら位置を保存します。

default.words に各ワードの {"min":0,"max":4294967295,"step":1} を指定できます。boundaries では特定の境界IDに条件を指定できます。必要ワード数は実際のrow数に従います。

照合する実測情報

観測IDの例は turn:1/camera:0。比較は checks の path と equals・oneOf・between のいずれかで指定します。実測値は計算途中の状態へ書き込みません。

編成・初期状態を編集

actorsは編成・能力値・状態・行動入力、camera.initialは初期カメラ条件です。row+4の値はここに固定せず、探索条件として指定します。

計算の境界
1つの共通プログラム
能力値・編成・行動表・初期状態をデータとして渡します。学習による近似や既知seedの正解表は使いません。
照合と状態更新を分離
候補から計算した状態を実測と比較します。複数候補が整合する場合は全て保持します。未対応処理は保留とし、不一致へ置き換えません。
ROMなしで実行
必要なグラフと定義はHTMLに含みます。ROM・フォント・描画資源の読込みは不要です。ONNX Runtime Webは固定した1.31.1版をjsDelivrから取得します。
入力定義の数は、戦闘全体の対応済み件数を意味しません。数値遷移とカメラで対応範囲が異なる場合は、具体的な境界を結果に残します。表示した速度はこの端末・この計算範囲の測定値です。
