# 自己対象への目標更新と row+4 候補照合

後続行動の対象が行動者自身になる場合も、共通の目標計算で扱う。ボス別の例外や既知 seed の結果表は追加しない。

## 修正した計算

元の dispatcher `func_ov025_021dffac` は、移動可能性を現在の行動の対象で判定した後、後続行動について cached target、secondary target、行動レコードの対象の順で対象を解決する。この再解決の結果は行動者自身でもよい。外部 row+4 が非ゼロなら fallback に進む一方、ゼロなら自己対象の `func_ov025_021e16c8` に到達する場合がある。

従来の decision グラフは `sourceRow == targetRow` を一律に未対応としていた。この制限を取り除き、既存の member / nonmember 共通計算へ接続した。start と対象 pivot の範囲チェックは維持する。

さらに、dispatcher は目標を更新した後に対象の goal を読み、行動者の face node に書く。行動者と対象が同じ場合、この読み出しには更新後の goal が必要である。commit グラフは、通常の AssignGoal、先行行動の auxiliary 復元、fallback のいずれでも、この読み書きの順を保持する。

変更対象は `rom-camera-goal-dispatch-decision4/12` と `rom-camera-goal-dispatch-commit4/12` の既存グラフ。新たなモデル名やダウンロードファイルは増えない。ホストは ONNX の返す処理種別に従って実行を進め、目標計算や対象の同一性による書き込みの判定は ONNX が行う。

仕様の根拠は matching commit `e0d1df250bfc554efe2fd37513a4ad3867a77b10` の `Combat/Overlay_25/func_ov025_021dffac.cpp`、`func_ov025_021e16c8.cpp`、`func_ov025_021e1f08.cpp`、`func_ov025_021e1f40.cpp`。各生成モデルにも入力したソースの SHA-256 を記録する。

## 候補の扱い

製品の row+4 入力は、実際に消費される境界ごとに、実在する compact roster の各行へ与える uint32 値である。デフォルトの探索域は各行の uint32 全域であり、以下の検証用 `{0, 1}` はその仕様を限定しない。

実測は各観測境界の照合条件にだけ使う。adapter に渡す lane は `id`、計算済み `state`、必要なときの `row4Input` だけである。不一致の枝は除外し、区別できない枝はすべて残す。採用した枝の乱数・戦闘・カメラ状態を計算結果のまま次ターンへ引き継ぐ。検証では、まとめて実行した結果と、1 候補・1 adapter 呼出ごとに JSON 保存して再開した結果を、枝の選択履歴・消費境界・照合履歴・最終状態まで比較する。

この表の複数ターン比較は、原本の数値計算と明示的な **outer camera → advance** 呼出列の比較である。outer から state 4 に移った後の archive 完了処理は含まれない。state 4 が追加の selector・乱数消費を生むことが別途判明しているため、この表だけでカメラを含むバトル全体の完成とはしない。その継続処理は配布済みの定義データから計算し、原本との別の直列比較で検証する。

測定に使用した provider は ONNX Runtime Web WASM。GPU 性能や既存 C++ 実装との速度比は、この正確性検証からは主張しない。

## 再実行

公開スクリプト `scripts/verify-common-battle-search-joint-rom.mjs` は、開発時に独立して取得した原本結果、初期入力だけのファイル、生成モデル、ORT の所在を引数で受け取る。例えば 3 ターンの別候補比較では、`--vary-word 2 --boundary-index 1` により 2 番目の実際の消費境界の第 3 行を変える。既定の代替値は元値がゼロなら 1、それ以外なら元値から 1 を引いた値。`--alternative` で別の uint32 値も指定できる。

ROM、原本結果、開発用ハーネスのメモリ配置は、製品の ONNX または HTML の実行条件ではない。元の関数を呼ぶ私有の検証ハーネスでは、作業領域を初回だけ作成し、以後は原本 `SafeAllocator::Reset` を呼ぶよう、重複作成の誤りを修正した。この検証側の修正を理由に、製品へアロケータや描画資源の実装を追加しない。
